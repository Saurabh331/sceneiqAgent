1. Executive Summary 
SceneIQ is an agentic screenplay intelligence platform that converts screenplays and related production documents into searchable, grounded, and actionable production knowledge. Users upload a script and ask natural-language questions about characters, scenes, locations, story arcs, and production complexity. 
The proposed MVP uses Google Gemini and the Google Agent Development Kit for reasoning and orchestration, a retrieval layer for screenplay grounding, and Parallel Search API as the recommended partner integration for fresh, traceable web context. The partner integration is invoked at runtime and is not merely referenced in documentation. 
Goal 
MVP outcome 
Reduce script review effort 
Generate grounded summaries and structured screenplay insights. 
Improve discoverability 
Enable semantic queries across scenes, characters, and locations. 
Add external context 
Use Parallel at runtime for current, source-linked research when requested. 
Demonstrate agentic behavior 
Execute deterministic multi-step flows with tool selection and response synthesis. 
 
2. Scope and Design Principles 
2.1 MVP Scope 
Upload PDF or text screenplay documents. 
Parse and chunk the script while retaining page, scene, and source metadata. 
Extract characters, locations, scenes, and key story arcs. 
Provide grounded conversational Q&A with source references. 
Identify explainable production complexity indicators, such as crowd scenes, multiple locations, night shoots, action sequences, or special-effects cues. 
Invoke Parallel Search API for external research, verification, and market or location context when appropriate. 
2.2 Out of Scope for the MVP 
Automated final casting decisions. 
Authoritative budget estimates or legal/compliance conclusions. 
Full video generation or feature-film rendering. 
Unattended actions that modify external production systems. 
2.3 Design Principles 
Ground answers in the uploaded screenplay. 
Keep AI-generated recommendations explainable and visibly separate from source facts. 
Minimize partner calls through intent routing and caching. 
Use least-privilege access, secret isolation, and auditable tool calls. 
Prefer a coherent end-to-end product experience over a collection of disconnected demos.

3.2 Logical Data Flow 
1. A user uploads a screenplay. 
2. The ingestion service validates the file, extracts text, identifies screenplay structure, and creates metadata-aware chunks. 
3. The knowledge layer creates embeddings and indexes chunks for semantic retrieval. 
4. The SceneIQ agent classifies the user intent and selects local screenplay tools, external research tools, or both. 
5. For script questions, the retrieval tool returns relevant passages with provenance. 
6. For current external context, the agent calls Parallel Search API at runtime and retains returned source metadata. 
7. Gemini synthesizes a response, clearly distinguishing screenplay evidence from external information and AI suggestions. 
8. Operational telemetry is recorded without storing secrets or unnecessary personal data.

5.1 Recommended Partner: Parallel 
Parallel is the strongest fit for the current SceneIQ concept because external web grounding extends screenplay analysis without replacing the core document intelligence experience. It also creates a visible runtime interaction that can be demonstrated clearly during judging. 
Location research: retrieve current public information relevant to a screenplay location. 
Comparable-content research: identify and summarize publicly available references while preserving source links. 
Production context: gather current public information requested by the user, such as location constraints or industry context, with citations. 
Freshness check: verify time-sensitive external claims instead of relying only on model memory. 
5.2 Runtime Integration Pattern 
The Orchestrator determines whether the question is document-only or requires external context. 
Document-only questions stay within the screenplay RAG flow. 
External-context questions call Parallel Search at runtime through a dedicated adapter. 
The adapter normalizes titles, URLs, excerpts, and retrieval metadata. 
The response composer distinguishes screenplay evidence, external sources, and AI-generated suggestions. 
Tool-call logs demonstrate that the partner service was genuinely invoked. 
5.3 Partner Evidence for Submission 
A public repository containing the actual partner SDK or MCP call. 
Configuration instructions using environment variables, without committing credentials. 
A demo segment showing the agent issue a partner-backed query and return sources. 
Logs or trace output proving runtime invocation. 
README architecture and data-flow explanation. 
6. Security, Privacy, and Responsible AI 
Control 
Design response 
Secrets 
Store API keys in Secret Manager; never expose them in the repository or client. 
Access 
Use IAM roles with least privilege for storage, model, and runtime access. 
Uploaded content 
Define retention and deletion behavior; avoid using confidential scripts in a public demo. 
Grounding 
Return screenplay references and external source links where applicable. 
Generated insights 
Label production risk and cost indicators as advisory, not authoritative. 
Prompt injection 
Separate system instructions from document content and validate tool arguments. 
Logging 
Avoid logging full screenplay text, credentials, or unnecessary personal information. 
 
7. Non-Functional Requirements 
Area 
MVP target / approach 
Reliability 
Graceful failures, retry only transient partner errors, and display actionable messages. 
Performance 
Asynchronous ingestion is an architectural option; interactive queries should use indexed chunks and bounded context. 
Scalability 
Stateless API and agent services on Cloud Run; storage and vector services scale independently. 
Explainability 
Show evidence passages, sources, and clear labels for inferred recommendations. 
Maintainability 
Modular tools, typed schemas, environment-based configuration, and automated tests. 
Cost control 
Cache stable research, limit context size, use intent routing, and capture token/tool usage.

10. Deployment View 
Frontend: Streamlit or lightweight web interface. 
Backend: FastAPI deployed to Cloud Run. 
Agent: Google ADK with Gemini, deployed through the selected Google Cloud agent runtime. 
Data: Cloud Storage for source files; BigQuery and a vector-capable retrieval service for metadata and embeddings. 
Partner: Parallel Search API or MCP called by a server-side adapter. 
Secrets: Secret Manager; no keys in client code. 
CI/CD: GitHub-based build and deployment pipeline with tests and secret scanning.
